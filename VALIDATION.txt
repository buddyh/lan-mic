- Native Apple Silicon Mac: 14 shared unit tests and 1 relay regression test.

Coverage
- Confirmed handoff, duplicate/late acknowledgements, other peer, release,
  selected-peer connection closure, restart and log rotation without replay.
- Persisted menu-bar display mode and both directions of name/platform labels.
- One-time star prompt eligibility, idle/foreground gating and persisted dismissal.
- Late recording streams on the former default follow an active handoff once;
  subsequent manual stream/default changes are preserved.
- Recording/default restoration, new recording streams, manual changes and
  recovery of a saved route after a crash.
- Feedback-source rejection, arbitrary frame boundaries, invalid/oversized
  frames, bounded decoder memory and full-duplex relay flush without newlines.
- Stereo downmix, clipping and 44.1 -> 48 kHz pitch preservation.

Live Linux ↔ Linux test passed
Two real Rust agents on one Linux host, private fixture handoff logs, a local
full-duplex relay, generated 440 Hz audio, real parec/pacat and PipeWire sources.
Latest run:
  Alpha -> Beta: 67,584 samples; RMS 3481.4
  Beta -> Alpha: 63,488 samples; RMS 3535.1
Returning focus restored the original recording input. Cutting the transport
during active forwarding restored the original default and muted the virtual
microphone. Default speakers were preserved. The production service resumed.
No real microphone was recorded; the fixture microphone contains only a tone.
This validates the Linux endpoint implementation in both roles, not hardware
interoperability across two separate Linux computers/compositors.

Existing Mac -> Linux evidence
The previous Rust build passed synthetic Mac tone -> Rust relay -> encrypted
SSH -> Rust receiver -> Linux virtual microphone (176,640 samples, RMS 3190.5),
with route restoration and idle mute. The user reported the audio working.
The current build was used with real Mac microphone -> Linux -> Codex dictation.
A live capture trace showed new dictation streams opening on a cached former
input after handoff. The Linux endpoint now follows those newly opened streams;
the user confirmed dictation working after the fix was installed.
The short diagnostic meter kept only sample count/RMS/peak, not audio files.

Not yet verified / required before broad release
- Linux -> Mac hardware audio: BlackHole 2ch was installed from the official
  package, checksum/signature/notarization verified. The Mac has restarted and
  the driver is now detected. Actual end-to-end receive audio still needs testing.
  A reverse-path fixture did not pass: the default switched briefly but returned
  to the physical input, and a separate CLI BlackHole capture probe read silence.
  CLI microphone permissions/probe behavior and default-route behavior remain
  unresolved. Do not treat status=receiving as verified usable Mac audio.
- This Linux computer currently defaults to a speaker monitor, not a physical
  microphone. Sending from Linux needs a selected/connected local microphone.
- Two separate Linux computers, additional compositors, USB hot-plug during a
  call, long-running soak tests, and physical listening-quality checks.
- Hosted CI passed on Linux and Mac. Release-package jobs also passed on Linux
  x86_64, Mac Apple Silicon and Mac Intel, including source and binary privacy
  checks. Run: https://github.com/buddyh/lan-mic/actions/runs/43075328538
- Developer ID signing/notarized app distribution and fresh-account first-launch

  Public repository and release status should be checked on GitHub directly.

Archive metadata
Linux package generation normalizes owner/group to numeric root (0:0), so local
release archives do not expose the builder’s login name. Public CI artifacts use
GitHub-hosted runner accounts; installed runtime state is never packaged.
